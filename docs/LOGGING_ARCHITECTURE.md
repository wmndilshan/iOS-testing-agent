# Logging Architecture

Status: **implemented** unless marked *planned*. Logging is operational diagnostics. It is observational only:
it cannot throw, cannot suspend, and nothing reads it to make a decision.

## Four different records

| Concept | Purpose | Owner | Persisted where |
| --- | --- | --- | --- |
| **Logger** (`AppLogger`) | Operational diagnostics for developers/operators | `Shared/Logging` (abstraction), `AgentInfrastructure/Logging` (destinations) | Off by default; optional `.logs/agent.log.jsonl` or stderr |
| **Run trace** (`RunTrace`) | Structured, redacted timeline of one run, shown in the UI | `Observability/Trace`, appended by `ScenarioExecutionController` | inside run history records |
| **Run history** (`RunHistoryStore`) | User-facing record of finished runs | `AgentInfrastructure/Persistence` | `.runs/` |
| **Security audit** | Evidence of authorization decisions | *planned*: `SecurityAuditRecorder` | not implemented |

They may share event vocabulary but have separate owners and lifetimes. Run history and traces are not
authorization; a log line is not evidence for the trusted spine. Today, authorization decisions are logged at
`notice` (`authorization.issued`, `approval.approved`) and recorded in the run trace; a dedicated, append-only
audit recorder is planned and **not implemented**.

## Layers

```
Shared/Logging            LogLevel, LogCategory, LogContext, LogEvent, LogValue, LogText, AppLogger, NullLogger, ContextualLogger
Security/Redaction        LogRedactor (the one redaction policy; builds on SecretRedactor)
AgentInfrastructure/Logging    LogDestination, ConsoleLogDestination (stderr), FileLogDestination (JSONL), InMemoryLogDestination,
                          DestinationLogger (level filter + redaction + fan-out), LogConfiguration, LoggerFactory
App                       AppCompositionRoot.makeLogger / logsDirectory (the only place that picks a log location)
```

Every layer may depend on `AppLogger` (Shared). Only Infrastructure implements destinations. Loggers are injected
(`ScenarioExecutionController.logger`, `LLMClient`, `LLMGateway`, `LLMActionProposalPipeline`); the default is
`NullLogger`, so there is no global logger and tests write nothing.

## Events

`LogEvent`: timestamp, level, category, `event` (lowercase dotted name, e.g. `execution.dispatch.started`), a short
plain message, optional `LogContext`, typed `fields`, optional duration and neutral `errorClass`.

Messages are single-line, bounded, and free of emoji/decoration (`LogText.sanitize`). Event names and categories
are checked by an architecture test: every logged name is valid dotted lowercase and every category is declared.

### Levels

| Level | Use |
| --- | --- |
| trace | Per-item development detail. Off by default. |
| debug | Internal decisions/state changes that help diagnose one run. |
| info | Normal lifecycle milestones (run started, step dispatched, request completed). Production default. |
| notice | Security/policy-relevant normal events (approval granted, authorization issued). |
| warning | Unexpected but handled (retry, rate limit, rejected proposal). |
| error | An operation failed and the caller sees a failure. |
| fault | A broken invariant/integrity failure. Should never happen. |

### Categories (closed set)

`application, lifecycle, configuration, llm, llm.network, proposal, validation, approval, authorization, execution,
tool, xctest, simulator, observation, verification, recovery, skills, persistence, inspector, integration,
security, performance`. Files do not invent categories.

### Correlation IDs and who owns them

| ID | Generated by |
| --- | --- |
| runID | `RunTrace` of the active scenario run |
| scenarioID / stepID | `ScenarioCatalog` |
| proposalID | proposal fingerprint (trusted domain) |
| approvalID | `HITLApprovalRequest.id` |
| snapshotID | the `Observation` the action is bound to |
| executionID | once per dispatch, by `ScenarioExecutionController` (also passed to the tool result) |
| requestID | once per network request, by `LLMGateway` |

## Instrumented today

- **Execution** (controller): `proposal.received|validated|rejected`, `approval.requested|approved|denied|expired`,
  `authorization.issued|rejected`, `execution.dispatch.started`, `execution.tool.started|completed`,
  `execution.observation.completed`, `execution.verification.completed`, `execution.step.failed`. Correlated by
  run, scenario, step, approval, snapshot, tool and executionID.
- **iOS actions** (`IOSToolAdapter`, `IOSInteractionExecutor`, observation performers): `ios.action.validated`,
  `ios.action.started`, `ios.action.completed`, `ios.action.failed` (with `actionType`, duration, success and a neutral
  `ActionFailureKind` as `errorClass`), and `ios.observation.started|completed` for accessibility observation. Correlated by
  run, scenario, step, executionID, snapshot and tool. Typed text, credentials and screenshot bytes are never logged (tested).
  Vocabulary mapping: an action being *proposed* is `proposal.received`; verification is `execution.verification.completed`
  (owned by the controller and `ScenarioVerificationService`, not the executor).
- **LLM semantics** (`LLMClient`, pipeline): `llm.request.started|completed|failed`, `llm.response.received|parse_failed`,
  `llm.proposal.created|rejected`, `llm.request.budget_exceeded`. Only provider label, model, counts, sizes, latency
  and a neutral `LLMFailureKind` are logged; **never prompt or response text**.
- **Network** (`LLMGateway`, the single owner): `llm.network.request.started|completed|retry|failed` with requestID,
  provider, endpoint (host + path, no query), payload/response byte counts, attempt, delay, status class and latency.
  No headers, API key, bodies or full URLs. `LLMClient`, the pipeline and the UI do not log transport events.

*Not implemented:* logging in skills, recovery, inspector and persistence; a redacted "LLM diagnostics" mode beyond
the `ATA_LLM_DIAGNOSTICS` flag being parsed (it currently adds nothing beyond the safe summaries above).

## Redaction (security-critical)

`DestinationLogger` redacts every event once, before any destination sees it, so a destination cannot forget.

1. **By key**: fields named like `password`, `apiKey`, `token`, `authorization`, `cookie`, `credential`, `username`,
   `typedText`, `signature`, `secret` are replaced wholesale.
2. **By value**: `SecretRedactor` (API keys, JWTs, bearer tokens, `password=` style) plus `.env`-style
   `NAME_KEY=value` lines, secret URL query parameters and `Cookie:` headers.
3. **By size**: strings over 500 characters are truncated (`[TRUNCATED n chars]`), so screenshots, response bodies
   and prompts cannot be logged by accident.

Redaction is recursive over arrays and objects and idempotent. Enabling `debug`/`trace` never disables it.
An architecture test also forbids passing `apiKey`, `password`, `Authorization` or credentials to a logger call.

## Configuration (read in one place: `LogConfiguration.load`)

| Variable | Meaning | Default |
| --- | --- | --- |
| `ATA_LOG_LEVEL` | minimum level | `info` |
| `ATA_LOG_CONSOLE` | plain lines to standard error | off |
| `ATA_LOG_FILE` | JSON lines to `<project>/.logs/agent.log.jsonl` | off |
| `ATA_LLM_DIAGNOSTICS` | reserved for redacted LLM diagnostics | off |

With nothing enabled the factory returns `NullLogger`: no destinations are created and nothing is written.

## What is *not* logging

The CLI's standard output (banners, stage tables, the approval prompt) and the app's `SNAPSHOT_SAVED:` marker are
user-facing terminal/tooling output, not logs, and are kept. Library code (`AgentCore`) has no `print`, `NSLog`,
`os_log`, `dump` or ad-hoc logger; an architecture test enforces it. The CLI's decorative `✓/✗/⚠` prefixes remain
because they are part of the operator-facing report, not log events.
